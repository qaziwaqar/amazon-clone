## One command

```bash
npm run deploy
```

[scripts/deploy.sh](scripts/deploy.sh). Idempotent — run it again any time to ship an update.

What it does: checks Node 20+ → installs deps → **runs lint + a production build locally as a gate** (a broken build never reaches the live URL) → signs you into Vercel (browser opens once) → links the project → generates `JWT_SECRET` and pushes it → deploys → verifies the URL returns 200 → prints the link.

Two details it handles that bite people doing this by hand:

- **`NEXT_PUBLIC_SITE_URL` chicken-and-egg.** That value is inlined at *build* time, so the first build can't know its own URL. The script sets it after deploy one and redeploys once — first run only.
- **Stable alias over deployment URL.** It prefers `<project>.vercel.app` rather than the per-deploy URL, which changes every time and is useless in a submission. Falls back if unreachable.

`JWT_SECRET` is generated, pushed, and never printed or committed.
